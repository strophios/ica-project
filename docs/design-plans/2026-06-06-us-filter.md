# US/not-US Pre-Filter Design

## Summary

This design builds a **US/not-US geographic pre-filter** — a text classifier that labels NYT headline+lede articles by whether they report a US-based event. The filter addresses a gap in the existing ICA pipeline: the immigration label-definition refinement work needs to distinguish US immigration events from foreign ones, and the existing R heuristic is too coarse for that purpose. Rather than building a rule-based system, the design trains a linear probe on the frozen DAPT backbone (the same domain-adapted RoBERTa encoder the CCA classifier uses), then calibrates its output to a probability score that downstream consumers can threshold to their own recall/precision needs.

The key engineering challenge is label construction: the NYT LDC corpus (1987–1995) includes datelines that reliably indicate where a story was filed, but datelines are a *proxy* for event location, not event location itself. The design uses datelines to build confident training labels while explicitly stripping them from the model's input (to prevent the model from simply reading the dateline rather than learning from the text). The resulting classifier is then applied to the dateline-less 1960–1986 API corpus — a transfer problem whose quality is measured by a small hand-labeled validation slice coded to actual event location, not filing location. The design is deliberately staged: R owns data extraction and label construction; Python owns the model, the leakage verification guard, and a new calibration module. Unlike the CCA classifier, this is a plain supervised binary classification task (confirmed positives *and* confirmed negatives exist), so there is no positive-unlabeled machinery.

## Definition of Done

A durable, reusable **US/not-US text-model pre-filter** for NYT headline+lede articles that labels the 1960–1995 NYT Archive API corpus by whether an article reports a **US-based event**, serving the immigration label-definition refinement and the eventual production filter.

**Target concept (clarified):** "article reports a US-based event" (the ICA-relevant notion). The newspaper **dateline is a training-label proxy** for this, not the target itself; the hand-labeled validation slice is coded to **actual event location** so we measure the proxy's real quality against what we care about.

### Primary deliverables

1. **Label-construction step.** Derive US/not-US labels from LDC datelines (1987–1995): extract the dateline prefix from `lead_paragraph` (pattern `^CITY[, STATE | , MONTH DD] (--|—|-) …`), convert place → US/not-US (NYT dateline style convention + gazetteer), and **strip the dateline from the model-input text**. Stripping is doubly required: it prevents label leakage (the label is derived from the dateline) and matches the dateline-less 1960–1986 input distribution.

2. **Trained US/not-US text classifier.** A linear probe on the frozen DAPT backbone, built on the modern model-construction abstractions (`ClassificationHead` + `build_endpoint_model`), trained on dateline-stripped text and applicable to the dateline-less 1960–1986 API corpus. Escalation to light fine-tuning (unfreeze top layers) only on validation evidence (pre-1986 underperformance) — escalate on evidence, not anticipation.

3. **`us` artifact.** A **calibrated probability score + boolean(s)** column written onto the article parquet(s), plus a **saved, reloadable model artifact** (weights + config sidecar) for re-application as the corpus expands. The recall-vs-precision operating point is a downstream, per-consumer threshold choice, not baked into the model.

4. **Validation protocol.** The "free" LDC↔API heuristic audit on the joinable 1987–1995 articles (real error rates, no hand-labeling), plus a small **pre-1986, event-location-coded hand-labeled slice** (piggybacked on the CCA validation set the user is building anyway), reporting model performance *and* the dateline-vs-event-location proxy gap.

### Success criteria

- Labels built from datelines with quantified extraction coverage/accuracy; leakage-stripping verified.
- Model trained and applied across 1960–1995; the score+boolean column materialized on the parquet(s).
- Validation report covering the 1987–1995 audit and the pre-1986 event-location slice, with the proxy gap measured and the probe-vs-fine-tune escalation decided on that evidence.
- A saved, reloadable model artifact + config sidecar exists.

### Out of scope

- Productionizing the conservative R heuristic (a separate, near-done dependency that unblocks the corrected-prior CCA retrain on its own track).
- Pre-1960 / post-1995 application *and its validation* (production durability is designed-for, not built or validated in this effort).
- FLPU / PU-specific Tier 5 validation (this filter is a plain supervised binary task; running it shakes out the shared training framework + local/cluster environment only — it is not a substitute for the FLPU + π≈0.02 Phase 7/8 runs).
- Wholesale migration of the R ETL into Python (unless the brainstorming hybrid-boundary analysis pulls in a specific piece).
- The immigration head itself / immigration label-definition refinement (the filter *serves* it; it does not perform it).

### Clarified constraints carried into design

- **R/Python prep boundary:** default to keeping data prep in R (RDS→parquet, fuzzy join, dateline→label, heuristic); Python owns the model. Hybrid remains open if brainstorming surfaces a large enough upside.
- **Design risk to track:** because we label with a filing-location proxy but validate against event location, an irreducible proxy gap exists. Validation quantifies it. If large, label enrichment beyond datelines (e.g., fusing the heuristic's keyword signal) becomes a live option.

## Glossary

- **DAPT (Domain-Adaptive Pre-Training)**: a fine-tuning step that adapts a general-purpose language model (here, RoBERTa) to the vocabulary and style of a specific domain (here, NYT headlines and ledes) by continuing masked-language-model training on in-domain text before any task-specific training.
- **RoBERTa**: a pre-trained transformer language model from Meta; the backbone encoder used throughout this project.
- **Linear probe**: a classifier that freezes the pre-trained encoder and trains only a single linear (dense) layer on top of it. Cheap to train because no gradient flows through the encoder. Also called a "frozen encoder" or "feature extraction" setup.
- **CLS features**: the representation from the `[CLS]` (classification) token position output by a transformer encoder, conventionally used as a fixed-length summary of the input sequence for classification tasks.
- **PN classification (positive-negative)**: standard supervised binary classification where both positive and negative class labels are available with confidence. Contrasted with PU learning.
- **PU learning (Positive-Unlabeled learning)**: a learning setting where only positive labels are known with confidence; the "negative" class is actually a mixture of true negatives and unlabeled positives. The CCA classifier uses this; the US filter explicitly does not.
- **FLPU loss**: this project's combination of Focal Loss and non-negative PU (nnPU) loss, used by the CCA classifier. The US filter uses plain BCE instead.
- **BCE (Binary Cross-Entropy)**: the standard loss function for binary classification tasks where both classes are labeled. Here used as `BinaryCrossentropy(from_logits=True)` (the model outputs raw logits, not probabilities).
- **nnPU (non-negative PU)**: the Kiryo 2017 variant of PU learning that clips the negative-risk estimate to prevent it from going negative during training. Not used in the US filter.
- **Dateline**: the geographic and date prefix that appears at the start of wire/newspaper story leads (e.g., `WASHINGTON, June 8 —`), indicating where the story was filed.
- **Dateline leakage**: the risk that a model trained to predict US/not-US learns to read the dateline directly rather than the underlying text, inflating apparent performance on data that includes datelines but failing on dateline-less inputs.
- **Label source / confident-label policy**: the system for tracking how each training label was derived (from a dateline, a desk-section heuristic, or unresolvable) and dropping ambiguous/conflicting cases to prioritize precision over coverage.
- **Proxy gap**: the difference between what the training label measures (filing location from the dateline) and what the model is actually meant to predict (event location). Measured explicitly on the hand-labeled validation slice.
- **Platt calibration**: a post-hoc calibration technique that fits a sigmoid (`σ(A·logit + B)`) on a held-out validation set, mapping raw logit outputs to calibrated probability scores. The `B` intercept absorbs class-balance skew, making it more flexible than temperature scaling for imbalanced data.
- **ECE (Expected Calibration Error)**: a metric measuring how well predicted probabilities match observed frequencies; a calibrated model with 70% predicted confidence should be correct ~70% of the time.
- **Brier score**: a proper scoring rule for probabilistic predictions (mean squared error between predicted probability and true label); lower is better.
- **Reliability diagram**: a plot of predicted probability (x-axis) vs. observed positive fraction (y-axis) used to visually assess calibration quality.
- **Temperature scaling**: a simpler calibration method that fits a single scalar `T` to divide logits (`logit/T`); less flexible than Platt because it has no intercept.
- **FCIS (Functional Core / Imperative Shell)**: a code organization pattern this project uses, where pure computation logic (the "functional core") is separated from side-effecting I/O code (the "imperative shell"). Source files carry `# pattern:` headers indicating their classification.
- **`ClassificationHead`**: this project's Keras layer abstraction for a classification head, supporting both standard mode (loss via `compile`) and endpoint mode (loss via `add_loss`). The US filter uses standard mode.
- **`build_endpoint_model` / `build_inference_model`**: project assembly functions that wire together a backbone and one or more `ClassificationHead`s into a training model (`LayerLRModel`) and a separate inference model.
- **`LayerLRModel`**: this project's `keras.Model` subclass that supports per-layer learning rate multipliers and hosts the diagnostic instrumentation.
- **`RunConfig`**: a frozen dataclass capturing all architectural and training hyperparameters for a run, serialized alongside the model weights as a JSON sidecar.
- **Shakedown run**: a short/capped training run (small number of steps) used to verify that the operational environment works end-to-end — paths, hardware, mixed precision, diagnostics — before committing to a full training run.
- **`mixed_float16`**: Keras's mixed-precision training policy that uses 16-bit floats for most computations (faster on GPU) while maintaining 32-bit master weights.
- **AP-style dateline abbreviations**: the Associated Press's standard list of state and city abbreviations used in datelines (e.g., `Wash.` for Washington state, `N.Y.` for New York). The NYT follows AP style conventions.
- **Gazetteer**: a geographic reference list or database mapping place names to classifications (here, US vs. non-US). The project uses curated CSVs in `context_data/` plus two new short curated lists (AP-30 standalone US cities, AP-46 standalone foreign cities).
- **DoCA (Dynamics of Collective Action)**: the existing protest-event dataset this project extends; used here as a source of confirmed CCA-positive article matches for the recall diagnostic.
- **LDC corpus (`LDC2008T19`)**: the NYT Annotated Corpus from the Linguistic Data Consortium, covering 1987–2007, which includes full article text, section/desk metadata, and indexer descriptors.
- **NYT Archive API**: a separate data source providing headline + lede for NYT articles from 1851 to present, without full text and without datelines.
- **Fuzzy join**: matching records between two datasets (here, LDC and API articles) using approximate string similarity rather than exact key equality, implemented in the existing R script `00_proc_and_matching_prep.R`.
- **`arrow::write_parquet`**: an R function (from the `arrow` package) for writing data frames to the Parquet columnar format, used here because it correctly serializes nested list-columns that other R↔Python bridges (`pyreadr`, `rpy2`) cannot handle.

## Architecture

Three stages with a single contract between them: an augmented parquet. R owns extraction and place-resolution; Python owns the model, leakage verification, and calibration. R → Python is *only* the parquet — Python never reads `.rds`, never re-parses datelines.

### Framing decision: supervised PN, not PU

The filter is **supervised positive-negative (PN) classification with plain binary cross-entropy** — explicitly *not* the positive-unlabeled (PU) setup the CCA classifier uses. The reason is structural: a foreign dateline (or a Foreign-desk assignment) is a *confirmed negative*, whereas in the CCA problem no negative is ever confirmable (any unlabeled article might be a missed positive). Because datelines and the desk/section heuristic yield genuine both-class labels, there is no prior to estimate, no nnPU clipping, no FLPU. This is the primary de-risking relative to CCA, and it is why running this filter validates the shared training *framework* but not the FLPU machinery.

### Stage A — R prep (extends `nyt_location_checking.R` + a new dateline module)

- **API ingest:** `nyt_archive_by_year/1960.rds…1995.rds` → parquet via `arrow::write_parquet`, which preserves the nested `keywords` list-column (`pyreadr`/`rpy2` cannot). API leads are dateline-less, so no stripping is needed on this side.
- **LDC label construction:** for each 1987–1995 LDC article, extract the dateline prefix from `lead_paragraph`, resolve place → US/not-US, assign `us_label` under the confident-label policy, and strip the dateline span.

**Emitted contract (columns added to the LDC parquet):**

| Column | Type | Meaning |
|---|---|---|
| `us_label` | bool, nullable | US (true) / not-US (false) / dropped (null) |
| `label_source` | enum `dateline\|heuristic\|conflict\|null` | provenance of the label |
| `dateline_place` | str, nullable | parsed place string (audit) |
| `stripped_text` | str | lead with dateline span removed — the model input source |
| `raw_text` | str | original lead, retained solely for the no-residue guard |

**Dateline extractor → place resolver → label policy:**

1. **Extractor** (positional): a regex isolates the leading caps block before the delimiter (em dash `—`, or `--`/` - ` variants), recognizing and removing the `Special to The New York Times` credit line and wire tags (`(AP)`).
2. **Matching mechanism:** tokenize → normalize → set-membership — *not* naive exact-match (brittle to extra/reordered tokens like `VANCOUVER, Wash., June 1`) and *not* free regex scanning (over-permissive, discards positional structure). Split the block on commas into fields; drop date fields via a date regex (`\b(Jan|Feb|…|Dec)\.?\s+\d{1,2}\b`); normalize remaining fields (strip periods/spaces: `"Wash."`→`wash`, `"N.Y."`→`ny`); match against sets.
3. **Resolver (structure-first, ordered):**
   - Split → `(city, qualifier)`.
   - qualifier is a **US state** (AP-abbrev or full name) → **US** (fires *before* any bare lookup, so `Paris, Texas` stays US).
   - qualifier is a **country** → **not-US**.
   - qualifier is a **date** or absent → the place is **bare** → consult only the short curated standalone lists (AP-30 US, AP-46 foreign).
   - bare and unlisted → **unresolved**.
   - **Invariant:** a bare token is *never* looked up in the long undifferentiated lists (`us-area-code-cities`, `countries.csv`). That is the collision trap — bare `LONDON` would spuriously hit London, OH. Consequence: `us-area-code-cities` is largely unneeded for dateline parsing (it belongs to the keyword heuristic).
   - **Guard:** 2-letter USPS codes (`OR`, `IN`, `OK`) collide with English words → match primarily on full-name + AP-abbrev; treat bare 2-letter codes as a guarded fallback.
4. **Label policy (fusion):** confident dateline → `us_label` from dateline (`label_source="dateline"`); else confident desk/section → from heuristic (`"heuristic"`); else `null` (dropped). A dateline/desk **conflict** (dateline US, desk Foreign, or vice versa) → dropped, tagged `"conflict"`. This is high-precision labels over complete training coverage — acceptable precisely because there is no prior to bias by dropping.

### Stage B — Python model (`src/`)

- **Input:** `headline + "</s>" + stripped_text` — the existing concatenation pattern pointed at `stripped_text`, achieved by parameterizing `data_from_parquet` on the lead-column name (not a fork).
- **No-residue guard:** the resolver's dateline detector is re-run over the assembled input column; zero matches asserted. Implemented as both a pytest and a runtime assertion at train entry. This is the load-bearing leakage check, and is why `raw_text` is retained.
- **Model:** frozen DAPT backbone (`load_dapt_backbone`) + a single `ClassificationHead(name="us")` in **standard mode**, with loss handled by `compile(loss={"us": BinaryCrossentropy(from_logits=True)})`. Assembled through the shared `assembly` + `LayerLRModel` path, so the diagnostic instrumentation and prediction-distribution metrics ride along — the framework/environment shakedown value, with BCE rather than FLPU.
- **Config/reproducibility:** a `us`-specific `RunConfig` (head name, frozen encoder, LR schedule, batch policy) with a JSON sidecar; `keras.utils.set_random_seed(200)`.
- **Training:** train/val/test split over the confidently-labeled LDC 1987–1995 set, reusing the seeded split. US/not-US is only mildly imbalanced (foreign is a sizable minority, not a rare class), so batch rebalancing is an optional, lightly-defaulted knob — *not* the PU ratio-batch machinery.

### Stage C — Calibration & artifact

- **Calibration:** Platt/sigmoid `σ(A·logit + B)`, fit on the **validation split at its natural US/not-US balance** (never the rebalanced training batches — rebalancing degrades calibration). Isotonic is ruled out (needs 1000+ per class, unstable under imbalance). For a single logit, Platt is strictly more flexible than temperature scaling (the `B` intercept absorbs class-balance skew). Calibration quality (ECE, Brier, reliability) is *evaluated* on the held-out test split and the pre-1986 event-coded slice — fit and evaluation never share data.
  - **Load-bearing concept:** calibrated probabilities are calibrated *to a distribution*. The labeled-val balance is a *proxy* for the dateline-less-dominated deployment distribution, not an exact match — an acknowledged, measured gap.
- **Output:** `us_score` (calibrated probability) is always written and is the durable contract; `us` (boolean) is a *downstream* choice (a documented default threshold, plus a recorded recipe for the CCA consumer to set a recall-protective threshold against the DoCA-matched set).
- **Artifact:** three sidecars travel together — `*.weights.h5`, `*.config.json` (`RunConfig`), `*.calibration.json` (`{method, A, B, fit_population, n}`).

### Validation & execution flow (nested gates)

The flow has three nested gates; the pre-1986 hand-labeled slice answers two distinct questions (does the model *transfer*? is the *proxy* good enough?) that trigger different responses.

0. **Prep + guard** — labeled parquet produced, no-residue guard passes, `label_source` breakdown sane. (Data-path gate.)
1. **Shakedown** — a short/capped run, local → cluster. *Operational* success criterion (it runs end-to-end, diagnostics fire, paths/env/`mixed_float16` behave). This is the Tier 5 level-1 short + cluster run; it is an **early** gate that admits entry to the full run, not a final step.
2. **Feature extraction + full train + in-distribution eval** — because the encoder is frozen, precompute CLS features *once* (the GPU-heavy step), then train the linear probe cheaply on top; evaluate on the 1987–1995 test split (in-distribution baseline).
3. **Transfer eval → escalation gate (inner loop)** — apply to the pre-1986 hand-labeled slice + DoCA recall diagnostic; compare to the in-distribution baseline. If transfer is materially weak → escalate to light fine-tuning (unfreeze top layers) → retrain → re-eval. Cheap until escalation (cached features); fine-tuning is the one full-encoder-cost step.
4. **Calibration** — on the *settled* model (after escalation resolves), per Stage C.
5. **Proxy-gap assessment → mitigation (outer, contingent loop)** — quantify dateline (filing) vs event-location agreement on the hand-labeled slice. *Only if the gap is large:* fuse the heuristic's keyword signal into labels → return to step 0 → retrain. A contingent branch, not a guaranteed step.
6. **Application** — the final calibrated model over the full 1960–1995 API corpus → `us_score` + `us`.

**Validation instruments:**
- **Free heuristic audit (1987–1995):** reuse the R fuzzy-join (`LDC2008T19/data/scripts/`) to match API↔LDC; measure the existing R heuristic's error against dateline labels, and verify `stripped_text` ≈ API lead for matched pairs (the transfer bet's core assumption). Caveat: error rates are conditional on joinability.
- **Pre-1986 hand-labeled slice:** event-location-coded, both classes, topic-diverse, stratified by era/desk, piggybacked on the CCA validation set; leans on the DoCA-matched set for the positive/CCA cell so hand-labeling concentrates on negatives, non-CCA positives, and ambiguous cases. The era-transfer ground truth.
- **DoCA-matched recall diagnostic:** the "CCA-consumer recall" on the held-out pre-1986 matched set, reported separately with its topic-skew caveat.

## Existing Patterns

This design follows established project patterns; the only new module is `src/calibration/`.

- **Model construction:** `src/model_setup/heads.py:ClassificationHead` (standard mode), `src/model_setup/assembly.py:build_endpoint_model`/`build_inference_model`, `src/model_setup/backbone.py:load_dapt_backbone`. The head abstractions are already multi-head-ready and support a simple binary head.
- **Preprocessing/data:** `src/preproc/preprocessor.py:ClassifierPreprocessor` (`label_keys` dict); `src/data_setup/data.py:data_from_parquet`/`create_classifier_data` (seeded split, `seed=200`). `data_from_parquet` is *parameterized* on the lead-column name rather than forked.
- **Config:** `src/cca_config.py:RunConfig` + JSON-sidecar pattern (`config_path_for_weights`); a parallel `us`-specific config follows it.
- **Diagnostics:** the `us` model rides the existing `src/diagnostics/` instrumentation and prediction-distribution metrics via the head's `metrics=` path — no new diagnostics code.
- **Platform paths:** `src/config.py` (local/cluster detection, `DTYPE_POLICY`). New data paths (API parquet, `context_data` gazetteer) are added here.
- **FCIS convention:** `src/calibration/` carries `# pattern:` headers — calibration math is Functional Core, sidecar I/O is Imperative Shell — mirroring `src/diagnostics/`.

**Reused R machinery (out-of-repo, sibling dirs):** `nyt_location_checking.R` (heuristic + gazetteer build from `context_data/` CSVs), `LDC2008T19/data/scripts/00_proc_and_matching_prep.R` (headline normalization + fuzzy join, for the audit).

## Additional Considerations

**Error handling / edge cases:**
- Dateline/desk conflicts and unresolved bare places are *dropped*, not guessed — recorded via `label_source` for analysis.
- The no-residue guard is a hard failure, not a warning: a leak silently inflates apparent performance, so it must block training.

**Future extensibility (designed-for, not built):**
- **GeoNames upgrade:** the gazetteer can swap to GeoNames `cities15000` (CC-BY-4.0) with population-based disambiguation if validation shows foreign-city misses — adopted on evidence, probe-first.
- **Production durability:** the saved artifact is the reusable production filter for corpus expansion (post-1995, pre-1960 toward 1851); that application and its validation are explicitly out of scope here.
- **Calibration seam:** the `Calibrator` interface is method/head-agnostic so the later multi-head + PU calibration work implements it rather than refactoring.

**Process note (implementation handoff):** the calibration notes (Phase 8) are to be developed dialogically with the user, who has deferred a conceptual calibration walkthrough to that drafting session as an iterative-development opportunity. Do not auto-generate them.
